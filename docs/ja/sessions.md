# セッションとプロジェクト

tuna は作業を 2 つの階層で整理します: プロジェクト（フォルダ）がセッション（タスク）をまとめ、すべてのセッションは閉じるまで tunad の中で動き続けます。

## セッション

**セッション**は作業の単位です: ひとつのタスク、ひとつのエージェント、ひとつの長時間動くプロセス。セッションには 1 つ以上の[ペイン](./panes.md)があり、それぞれでシェルかプログラムが動きます。

| アクション                     | ショートカット                                     |
| ------------------------------ | -------------------------------------------------- |
| 新規セッション                 | <kbd>⌘</kbd> <kbd>T</kbd>                          |
| ホームフォルダで新規セッション | <kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>T</kbd>             |
| セッションへ移動…              | <kbd>⌘</kbd> <kbd>P</kbd>                          |
| 会話を再開…                    | <kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>O</kbd>             |
| 対応が必要なセッションへ移動   | <kbd>⌘</kbd> <kbd>J</kbd>                          |
| 次 / 前のセッション            | <kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>]</kbd> / <kbd>[</kbd> |
| セッション名を変更             | <kbd>⌘</kbd> <kbd>R</kbd>                          |
| セッションを閉じる             | <kbd>⌘</kbd> <kbd>⇧</kbd> <kbd>W</kbd>             |

`fix-login-redirect` や `review-pr-42` のように、セッションにはタスクにちなんだ名前を付けましょう。サイドバーで見つけやすくなり、[CLI](./cli.md) から指定しやすくなります。

### 新規セッションの開始場所

`new-session-directory` 設定でフォルダを選びます:

- `current`（デフォルト）: 今いるセッションのディレクトリ
- `project`: プロジェクトのルートフォルダ
- `home`: ホームフォルダ

<a id="how-an-unnamed-session-is-named"></a>

### 名前のないセッションの名前

あなたかエージェントがセッションに名前を付けるまで、サイドバーに表示される名前は `session-name` 設定（設定の **セッション名の付け方**）で決まります:

- `focused`（デフォルト）: 今いるペインで動いているプログラムのタイトル。シェルだけが動いているペインは、最も対応が必要なペインに譲ります。
- `lead`: 最も対応が必要なペインで動いているプログラムのタイトル。作業中のエージェントや、あなたの対応を待っているエージェントなど
- `folder`: 何が動いているかにかかわらず、最初のペインのフォルダ

## プロジェクト

**プロジェクト**はフォルダです。tuna はサイドバーでセッションをプロジェクトの下にまとめます。<kbd>⌘</kbd> <kbd>O</kbd> で開くか、セッションの開始ディレクトリから `tuna new` に選ばせます。

```sh
tuna projects            # プロジェクトを一覧
tuna new -p my-app       # 名前で指定したプロジェクトでセッションを開始
```

## tunad

セッションは、アプリが必要に応じて起動するデーモン **tunad** の中で動きます。tuna は tunad を映すウインドウです:

- tuna を終了しても、すべてのセッションは動き続けます。
- もう一度 tuna を開くと、スクロールバックも含め、すべてのセッションが元のまま表示されます。
- 再起動のあとなど tunad 自体が再起動すると、tuna はセッションをそれぞれのディレクトリで再び開始します。`restore-sessions = false` でオフにできます。
- そのエージェント向けに [tuna のスキル](./agents.md#install-the-skill)をセットアップしてあれば、Claude Code、Codex、Pi、OpenCode が動いていたペインは、エージェント自身の再開オプションと同じように会話を再開します。ほかのプログラムは勝手に再起動しません: そのペインはシェルに戻ります。`resume-agents = false` でオフにできます。

```sh
tuna daemon status       # tunad は動いている？
tuna daemon restart      # 再起動する（セッションは再び開始）
tuna daemon stop         # 停止して、すべてのセッションを終える
```

### 終了したセッション

設定 › 一般 › **セッション履歴**、または `session-history = true` をオンにすると、いまどのペインでも動いていない会話をサイドバーの下部に一覧します。会話は再び動き出すとこの一覧から外れます（[詳しく](#past-conversations)）。**終了済み** は最新の 5 件を表示します。見出しをクリックすると開き、**すべて表示** で全部を表示します。ホストごとに最新の 50 件を残します。ほかのホストの会話も、ホスト名のタグ付きで並びます。

- クリックすると、そのフォルダとプロジェクトで、もとのセッション名のセッションが開き、パレットと同じように会話を再開します。
- ポインタを重ねてアーカイブボタンをクリックすると、その会話が **アーカイブ** に移ります。
- 右クリックすると、再開、アーカイブ、忘却、ID やフォルダのコピー、フォルダの表示ができます。**終了済み** を右クリックするとすべてアーカイブ、**アーカイブ** を右クリックするとすべて忘却できます。忘却しても tuna の一覧から消えるだけで、エージェント自身のファイルは残ります。
